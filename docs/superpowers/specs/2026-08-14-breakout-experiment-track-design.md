# 돌파(breakout) 실험 트랙 설계 — 헌장 v4.0

날짜: 2026-08-14
상태: 운영자 승인 (설계 단계)
배경: 운영자의 원래 의도는 "위험이 있어도 자주 거래하며, 그 안에서 문제점을 튜닝하며
조금씩 다듬어가는 것"이다. 시드 약 9만원은 잃어도 타격이 없는 수업료 예산으로 시작했다.
그러나 현행 시스템은 검증·안전 중심으로 수렴해 거래가 거의 잡히지 않는다
(2026-08-14 실측: 마지막 진입 10일 전 · 최근 7일 0건 · 30일 5건 · 인큐베이션 0/100건).

## 0. 목적과 비목적

**목적**
- 하루 3~10건 수준의 거래 빈도를 만들어 튜닝 표본을 빠르게 쌓는다.
- 모든 거래에 진입 컨텍스트를 저장하고, 주간 코호트 리포트로
  "어떤 조건의 거래가 손실인가"를 실거래 데이터로 밝힌다.
- 검증 트랙(rsi2 인큐베이션)은 오염 없이 병행 유지한다.

**비목적 (정직한 한계)**
- 이 트랙의 1차 산출물은 수익이 아니다. 과거 연구(14차 H4)에서 돌파 계열 롱은
  유의하게 음수였다. 한계 거래의 기댓값이 0~음수임을 알고 수업료
  (왕복 비용 거래당 약 0.15~0.25%)를 내며 데이터를 사는 것이다.
- §11 백테스트 통과를 가동 조건으로 삼지 않는다(운영자가 명시적으로 선택).
  캘리브레이션 백테스트는 판정이 아니라 시작값 선택·빈도 예측 용도다.

## 1. 전체 구조 — 두 트랙

```
계좌 (약 9.1만원, 실계좌 잔고를 런타임에 읽음)
├── 검증 트랙: rsi2 · rsi2_15m  — 규칙 변경 없음, 인큐베이션 계속
│     배분 상한: 자본의 2/3  (실험 예산 침범 방지. 실효 리스크 2.4% → 약 1.7%)
└── 실험 트랙: breakout (신규) — 주력. 자주 거래하며 주간 튜닝
      예산: 건당 10,000원 고정 × 동시 최대 3포지션 = 30,000원
```

- 실험 트랙 거래는 전략명(`breakout`)으로 분리 기록되며 인큐베이션 집계에서 제외된다.
- rsi2 배분 축소(1.0 → 2/3)는 거래당 %성적에 영향이 없으므로 인큐베이션 표본은
  오염되지 않는다. 단 계좌 단위 성장률·MDD 궤적은 달라진다 — 이 문서가 그 기록이다.

## 2. breakout 전략 규칙 (전부 튜닝 축, 시작값은 §7 캘리브레이션으로 확정)

| 규칙 | 시작값(안) | 축 이름 |
|---|---|---|
| 봉 | 5분봉 | `timeframe` |
| 진입 | 종가가 직전 20봉(현재봉 제외) 최고가 돌파 | `breakout_bars` |
| 거래량 확인 | 현재봉 거래량 ≥ 최근 20봉 평균 × 1.5 (0이면 끔) | `vol_mult` |
| 초기 손절 | 진입가 − 1.0×ATR(14), 하한 MIN_STOP_RATIO(1%) | `atr_stop_mult` |
| 익절 | 트레일링 스톱: 진입 후 고점 − 1.5×ATR(진입 시점 ATR) 하회 시 청산 | `trail_atr_mult` |
| 시간손절 | 12봉(1시간) 경과 시 미실현수익 < +0.3%면 청산, 이상이면 유지 | `time_stop_bars`, `time_stop_min_profit` |
| 변동성 게이트 | 없음 (`min_atr_ratio=0.0`) — 기록만 | — |
| 추세 필터 | 없음 — 진입 시점 `trend_up`을 기록만 | — |
| 레짐 필터 | 없음 (`always_active=True`) | — |

- 고정 익절가는 없다. 손절/시간손절/트레일링 셋 중 하나로만 나간다.
- 같은 종목 재진입: 기존 규칙 유지(동일 코인 중복 보유 금지). 청산 후 재돌파 시 재진입 가능.
- 유니버스: 기존 스크리너 그대로(스프레드 ≤0.1% 등). 실험 트랙이라고 넓히지 않는다 —
  빈도는 게이트 부재에서 나오고, 넓은 스프레드는 수업료만 키운다.

### 진입 컨텍스트 기록 (모든 진입 시 JSON 저장)
`breakout_bars/vol_mult/trail_atr_mult` 등 사용 파라미터 전부 · 돌파폭(직전 고점 대비 %) ·
거래량비 · ATR% · trend_up(1시간봉 EMA200) · 스프레드(진입 직전 실측) · KST 시각(시간대 코호트용) ·
헌장 지문. 파라미터를 기록하므로 튜닝 후에도 "몇 주차 설정의 성적"으로 코호트 비교가 가능하다.

## 3. 헌장 통합 (charter.py, v4.0)

- `EXPERIMENTAL_STRATEGIES: frozenset = {"breakout"}` 범주 신설.
  - ACTIVE_STRATEGIES 허용 조건: VALIDATED ∪ INCUBATING ∪ **EXPERIMENTAL**.
  - `EXPERIMENT_MAX_ORDER_KRW = 10_000` — `position_cap_for()`가 강제
    (인큐베이션 5,000원 상한과 같은 메커니즘). easy_teaching 사고(검증 0건 전략이
    자본 1/3로 실계좌 진입)의 재발 방지 장치를 유지하면서 "작게는 실험해도 된다"를
    규칙으로 만든다.
- `ACTIVE_STRATEGIES = ("rsi2", "rsi2_15m", "breakout")`.
- 동시 포지션: 전역 1개 → **트랙별 상한**으로 변경.
  - `MAX_POSITIONS_VALIDATED = 1` (기존과 동일) · `MAX_POSITIONS_EXPERIMENTAL = 3`.
  - `RiskManager.can_enter(strategy)`가 전략의 트랙을 보고 판정한다.
- `ALLOC_PER_STRATEGY_RATIO = 2/3` (검증 트랙 배분 상한).
- 서킷 (운영자 결정, 절대 % — 두 트랙이 한 계좌를 공유하므로 R 단위 대신 절대값):
  - `DAILY_LOSS_LIMIT_RATIO = 0.05` (일 −5%, 약 −4,500원에서 당일 정지)
  - `MAX_DRAWDOWN_RATIO = 0.50` (고점 대비 −50%에서 전면 정지, 재가동 수동)
  - `MAX_CONSECUTIVE_LOSSES = 12` 유지 (일 경계 자동 리셋 포함, 두 트랙 합산).
    돌파 전략은 승률이 낮고 드문 큰 승리로 버는 구조라 12연패가 월 1~2회 나올 수 있다 —
    발동 빈도를 주간 리포트로 관찰하고, 잦으면 트랙별 분리를 다음 개정에서 검토한다.
- `StrategySpec` 확장 필드: `breakout_bars` · `vol_mult` · `trail_atr_mult` ·
  `time_stop_min_profit` (기본값은 기존 전략 동작을 바꾸지 않는 값).
- 지문(fingerprint): ACTIVE_STRATEGIES·스펙·§5 값이 바뀌므로 자동 갱신 → 배포 시 재승인 필요.

## 4. 실행 경로 변경 (bot/)

- `strategies/breakout.py` — `BreakoutStrategy(BaseStrategy)`. 진입 판정과 meta(컨텍스트) 생성.
  청산은 가격 기반(Position)이므로 역신호 EXIT는 내지 않는다.
- `bot/position.py` — 트레일링 스톱 지원: `trail_atr_mult`가 있으면
  `고점 − trail_atr_mult×entry_atr` 하회 시 청산. 시간손절에 `time_stop_min_profit` 조건 추가.
- `bot/risk_manager.py` — `can_enter(strategy)` 트랙별 상한 · 절대 % 서킷.
- `bot/trader.py` — ALL_STRATEGIES 등록 · entry 로그에 컨텍스트 JSON 전달.
- `incubation/logger.py` — `context` TEXT 컬럼 추가(기존 DB는 ALTER TABLE로 마이그레이션).
- `incubation/progress.py` — 집계 대상을 ACTIVE에서 **VALIDATED ∩ ACTIVE**로 좁힌다
  (breakout이 인큐베이션 표본에 섞이지 않게).

## 5. 튜닝 루프

1. **주간 코호트 리포트** (`deploy/weekly_report.py` 확장 + `incubation/cohort.py` 신설):
   breakout 거래를 축별로 쪼개 승률·거래당 손익·건수를 표로 만든다.
   - 축: 거래량 확인 여부 · trend_up 여부 · KST 시간대(4시간 버킷) · 종목 ·
     ATR% 밴드 · 돌파폭 밴드 · 설정(지문) 버전
   - 30건 미만 코호트는 "표본 부족"으로 표시하고 판정하지 않는다(기존 원칙 유지).
   - 대시보드 `/api/experiment`로도 노출.
2. **주간 튜닝 세션**: 운영자가 리포트를 보고 Claude와 함께 파라미터 1~2개를 조정.
   조정은 헌장 개정(버전업 + 지문 갱신)으로만 한다 — 컨텍스트에 지문이 남아
   설정 버전별 성적 비교가 자동으로 된다.
3. 조정 이력은 이 문서 하단 "튜닝 로그" 절에 누적 기록한다.

## 6. 테스트

- 기존 전체 테스트 통과 유지 (`test_charter.py`의 ACTIVE 목록 단언 갱신).
- 신규: ① breakout 진입/트레일링/시간손절 단위 테스트 ② EXPERIMENTAL 주문금액 상한 강제
  ③ 트랙별 동시 포지션 상한 ④ 인큐베이션 집계가 breakout을 제외하는지
  ⑤ 절대 % 서킷 발동 ⑥ context 컬럼 마이그레이션(기존 DB 호환).

## 7. 캘리브레이션 백테스트 (가동 전 1회)

`backtesting/research/lab_breakout.py` — 캐시된 2년 5분봉으로
`breakout_bars {12,20,36} × vol_mult {0,1.5,2.0} × trail {1.0,1.5,2.0}` 그리드를 돌려
**하루 거래수·승률·거래당 손익**을 표로 낸다.
- 선택 기준: 하루 3~10건 범위 안에서 기댓값이 가장 덜 나쁜 조합.
- 결과가 전부 음수여도 가동한다(운영자 결정). 대신 예상 수업료(월 예상 손실)를
  가동 전에 보고한다.

## 8. 배포 순서

1. 로컬 전체 테스트 통과 → 캘리브레이션 실행 → 시작값 확정(운영자 보고)
2. commit → push → GitHub Actions 자동배포 (이 시점 서버는 지문 불일치로 모의 강제)
3. 서버 `.env` `LIVE_CHARTER_ACK` 새 지문으로 갱신 + recreate
4. `/api/status`로 `dry_run=false` · `forced_paper=""` · strategies에 breakout 확인
5. 첫 주: 매일 거래 발생 여부만 확인, 7일 후 첫 코호트 리포트
