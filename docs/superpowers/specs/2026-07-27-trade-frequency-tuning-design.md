# 거래 빈도 확대 검증 설계 (2026-07-27)

## 문제

라이브 봇(헌장 v2.2, `rsi2` 5분봉 + `rsi2_15m` 15분봉)의 진입 신호가 거의 발생하지 않는다.
백테스트 기대 빈도가 하루 1.21회이고, 2026Q3 현재 구간은 ATR(14)/가격 ≥ 0.6%를 만족하는
봉 비율이 majors에서 0%라 신호가 0건이다. 운영자 판단: **하루 1회 미만의 빈도로는 자본 증식
속도가 무의미하다.**

운영자 요청은 세 가지다.
1. RSI(2) 진입선과 ATR% 게이트가 과도하게 타이트한지 재검토 — 빈도를 늘리되 손해 없는 값 탐색
2. 1분봉 추가 검토
3. 위를 전부 백테스트로 판정

## 이미 알고 있는 것 (이 설계의 전제)

이전 세션(2026-07-26) 검증에서 확인된 사실이며, 이번 작업은 이것을 재확인하는 데 시간을
쓰지 않고 **완화의 대가를 정량화**하는 데 집중한다.

| 사실 | 근거 |
|---|---|
| RSI(2)≤10 완화는 홀드아웃에서 −0.052%/거래(t−3.01)로 반전 | `lab_final.py` 2년 12종목 |
| ATR 게이트 완화는 기댓값을 단조 감소시킨다 (0.6%→0.3%: +0.199%→−0.050%) | `lab_screen.py` IS 스윕 |
| 타임프레임별 왕복비용/한 봉 평균움직임 = 5분 77% · 15분 46% · 1시간 20% | `lab_15m.py` |
| 5분+15분 병행으로 빈도 0.78→1.21회/일, t 3.48→5.06 | `lab_combined.py` |
| 왕복비용 0.25%에서 검증된 엣지는 소멸(exp +0.015%, t+0.50) | `lab_verdict.py` |
| 신호 다음 봉 시가 진입을 쓰지 않으면 허구의 엣지가 나온다 | xrev: t+21.6 → −0.106%(t−10.9) |

즉 **같은 종목·같은 타임프레임에서 문턱만 낮춰 빈도를 얻는 경로는 이미 막혀 있다.**
빈도의 정당한 출처는 (a) 독립적인 신호원 추가 = 타임프레임 확장, (b) 거래 가능 종목 수 확대다.

## 합격 기준 (사전 등록 — 실행 전 확정, 사후 변경 금지)

운영자가 선택한 목적함수는 **일일 기댓값 최대화**다.

```
목적함수   일일 기댓값 = 거래당 exp × 하루 거래수
하한 ①    walk-forward OOS exp > 0 AND t > 2 (다중비교 보정 후)
하한 ②    왕복비용 0.25% 스트레스에서도 exp > 0
하한 ③    포트폴리오 MDD ≤ 20%
```

하한 ②가 실질적 관문이다. 빈도를 늘리면 거래당 마진이 얇아지므로 비용 민감도가 커진다.
심야에 중형 종목 스프레드가 2~4배 벌어진다는 실측이 있으므로, 이 스트레스를 통과하지 못하는
조합은 다른 지표가 아무리 좋아도 탈락시킨다.

거래당 exp가 현행(+0.259%)보다 낮아도 일일 기댓값이 높으면 채택 후보가 된다.
단 하한 3개는 예외 없이 적용한다.

**헌장 §11과의 관계**: 위 세 하한은 **이번 연구의 선택 기준**이고, §11(거래≥100 · 승률≥55% ·
PF≥1.5 · MDD≤20%)은 **실전 배포 관문**이다. 둘은 대체 관계가 아니다. 일일 기댓값 최대 구성이
§11을 통과하지 못하면 그 사실을 명시해 보고하고, 배포 여부는 운영자 결정에 맡긴다.
§11 기준 자체의 개정(손익비별 재정의 논의)은 이번 범위가 아니다.

## 방법론 (결론의 신뢰도를 정하는 부분)

문턱 스윕은 본질적으로 과최적화 기계다(th=10 사례가 그 증거). 판정 순서를 고정한다.

1. **선택은 선택구간에서만** — `SELECTION_START = 2025-12-29` 이후 약 7개월에서 그리드를 훑는다.
   홀드아웃 17개월은 건드리지 않는다.
2. **주 증거는 walk-forward** — 7폴드, 폴드마다 파라미터 재선택. 사후선택이 구조적으로 불가능하다.
   문턱 완화가 진짜 이득이면 여기서 나타난다.
3. **홀드아웃 조회 예산을 미리 정한다** — 축 2·3·4에 각 1회, 최종 통합 구성에 1회 = **총 4회**.
   초과하지 않으며, 실제 조회 횟수를 결과 문서에 기록한다.
   조회할수록 홀드아웃은 홀드아웃이 아니게 된다.
4. **다중비교 보정** — 홀드아웃 조회 횟수 기준 Bonferroni로 필요 t를 상향한다.
   (선례: 16조합 중 선택 → 필요 t≈2.9)
5. **체결·비용 모델은 변경 금지** — `ENTRY_DELAY=1`(다음 봉 시가), 수수료 `FEE_ROUNDTRIP=0.1%`
   + 종목별 실측 스프레드, intrabar 체결(같은 봉에서 손절·익절 동시 도달 시 손절 우선),
   신호창 200봉 고정(라이브 `get_candles`와 동일).
6. **포트폴리오 수준까지 계산** — 빈도가 3배가 되면 동시 3포지션 슬롯이 포화된다.
   "신호 3배 = 거래 3배"가 성립하지 않으므로 `portfolio.run()`의 계좌 곡선으로 최종 비교한다.

## 실행 순서 (의존성)

축 사이에 데이터 의존성이 있으므로 순서를 고정한다. API를 쓰는 단계(0·1·4의 수집)는
서로 겹치지 않게 **단독 실행**한다.

```
축 0  스프레드 재측정 (API, 약 30분)
  └─ 모든 축의 비용 입력. 여기서 확정하지 않으면 이후 결과를 다시 돌려야 한다
축 1a 청크 수집기 수정 + 1분봉 2년 수집 (API, 약 2.2시간, 단독)
축 4a VANA·FIL 5분봉 수집 (API) ← 축 1a 완료 후
  ↓ (이하 네트워크 불필요, 병렬 가능)
공통 코어 lab_tfcore.py + 테스트
축 2  문턱 frontier — 5분·15분에서 먼저 (라이브 현행 설정 기준)
축 3  타임프레임 스캔 — 1분·30분·1시간 추가
축 2' 축 3 생존 타임프레임에 대해 문턱 frontier 재실행
축 4  미검증 종목 판정
최종  포트폴리오 통합 → 하한 3개 판정 → parity 확인 → 헌장 개정안
```

축 1a가 실패하거나 시간이 초과되면 **1분봉만 미판정으로 남기고 축 2·3·4를 진행한다**
(1분봉은 사전 예상이 기각이므로 다른 축을 막지 않는다).

## 축 2 — 문턱 2D frontier (`lab_frontier.py`)

운영자가 직접 질문한 부분. 완화의 대가를 표로 확정한다.

- 그리드: RSI(2) 진입선 `{2, 3, 5, 7, 10, 15}` × ATR 게이트 `{0.4, 0.5, 0.6, 0.8, 1.0, 1.2}%`
  = 36조합. 게이트는 타임프레임별로 환산한 값을 기준으로 스케일한다.
- 대상 타임프레임: 5분·15분(현행 라이브) 우선, 축 3에서 생존한 타임프레임 추가
- 출력 컬럼: `거래수 · 하루거래수 · 승률 · PF · 거래당 exp · 일일 기댓값 · t · 0.25% 스트레스 exp`
- 선택구간에서 표를 만들고, walk-forward로 판정, 홀드아웃은 최종 후보 1회
- 낙관/보수 스프레드 두 벌 병기

목표 산출물: "th 3→7로 완화하면 빈도 N배, 일일 기댓값 X% → Y%" 형태의 확정 수치.

## 축 3 — 타임프레임 확장 (`lab_tfscan.py`)

비용/움직임 비율의 반대 방향. 5분+15분 병행이 t를 3.48→5.06으로 올린 그 방식을 확장한다.

### 설계 결정: 추세 필터 스케일

1분~30분봉 전략은 **1시간봉 EMA200**(라이브와 동일), 1시간봉 전략은 **4시간봉 EMA200**을 쓴다.
1시간봉 전략에 1시간봉 EMA200을 쓰면 진입봉과 필터봉이 같아 자기참조가 된다.

### 파라미터 환산 (스윕 시작점)

시간손절은 8시간으로 고정(현행 설계 의도 유지). 게이트·손절은 √봉길이로 스케일한 초기값에서 스윕.

| TF | 게이트 초기값 | 손절/익절 | 시간손절 | 비용/한 봉 움직임(예상) | 데이터 |
|---|---|---|---|---|---|
| 1분 | 0.27% | 1.5% | 480봉 | ~171% | 신규 수집 |
| 5분 | 0.6% (현행) | 2.5% | 96봉 | 77% | 보유 |
| 15분 | 1.0% (현행) | 3.0% | 32봉 | 46% | 5분봉 리샘플 |
| 30분 | 1.4% | 4.0% | 16봉 | ~33% | 5분봉 리샘플 |
| 1시간 | 2.0% | 5.0% | 8봉 | 20% | `minute60` 캐시 / 5분봉 리샘플 |

30분·1시간봉은 신규 데이터 수집이 필요 없다(기존 5분봉 2년 캐시로 리샘플 가능).

## 축 4 — 미검증 종목 검증 (`lab_universe.py` 확장)

## 공통 코어 (`lab_tfcore.py`)

축 2·3·4가 공유하는 로직을 한 곳에 둔다. 기존 `lab_15m.py`에 흩어져 있는 것을 승격시킨다.

| 함수 | 역할 |
|---|---|
| `resample(df1m, tf)` | 1분봉 → 임의 타임프레임 집계 |
| `params_for(tf)` | 봉길이별 게이트·손절·시간손절 환산 |
| `trend_on(df, filter_tf)` | 상위 타임프레임 EMA200 위 여부를 대상 봉에 정렬(직전 완성봉 기준) |
| `signals(df, th, gate)` | RSI(2) 진입/청산 신호 배열 |
| `run_market(...)` | `fastsim`으로 한 종목 시뮬 (비용·체결 모델 고정) |
| `daily_exp(stats, days)` | 일일 기댓값 계산 |
| `judge(stats, ...)` | 사전 등록한 하한 3개 판정 + 필요 t(보정 후) 계산 |

경계 조건: 각 함수는 자기 입력만 보고 판단하고, 비용·체결 상수는 `lab_screen`에서 import해
한 곳에서만 정의한다(모델이 두 군데 있으면 검증 코드와 배포 코드가 어긋난다).

## 최종 통합과 배포 관문

1. 네 축의 생존 조합을 모아 `portfolio.run()`으로 계좌 곡선 비교
   (동시 3포지션 `MAX_CONCURRENT_POSITIONS=3` · 동일코인 중복 금지 · 일일 손실 한도 3%)
2. 일일 기댓값이 최대인 구성을 선택하고 하한 3개를 판정
3. 통과 시에만: `lab_live_parity.py`로 라이브 전략 클래스와 신호 봉단위 일치 확인(불일치 0 필수)
4. 헌장 개정안 제시 — 새 타임프레임·파라미터·블랙리스트 반영. 개정 시 서버 `.env`의
   `LIVE_CHARTER_ACK` 갱신이 필요하다(§9.7)
5. 통과 조합이 없으면 그 결론을 그대로 보고한다. 기준을 사후에 낮추지 않는다

## 테스트

- `lab_tfcore` 리샘플: 1분봉 → 5분/15분 리샘플 결과가 업비트 실제 5분/15분 캐시와 완성봉 일치
- `params_for`: 시간손절이 모든 타임프레임에서 8시간에 해당하는 봉 수인지
- `trend_on`: 상위 타임프레임 값이 **직전 완성봉**만 참조하는지(미래 정보 누출 방지) —
  경계 시점 인덱스를 직접 검증
- `judge`: 하한 3개가 각각 독립적으로 작동하는지(경계값 케이스)
- 청크 수집기: 중단 후 재실행 시 중복 봉 없이 이어붙는지(인덱스 유일성)
- 기존 `verify_fastsim.py` · `lab_live_parity.py`는 그대로 통과해야 한다

## 예상 결론 (사전 기록 — 확증 편향 방지용)

작업 전 예상을 남긴다. 결과가 다르면 그 차이가 발견이다.

1. 문턱 완화는 빈도를 늘리지만 일일 기댓값은 개선하지 못한다(하한 ②에서 탈락)
2. 1분봉은 기각된다(비용/움직임 비율 약 171%)
3. 빈도 증가의 실질적 출처는 30분·1시간봉 병행과 종목 수 확대다
4. 보수 스프레드를 적용하면 중형 종목 상당수가 탈락하고, 그 결과 종목 확대 여지도 줄어든다

## 범위에서 제외

- 신호 자체의 교체(새 전략 발굴) — 이번은 기존 검증된 신호의 파라미터·적용 범위 문제다
- 지정가(패시브) 주문으로 스프레드를 아끼는 방안 — 불리할 때만 체결되는 선택 편향이 생기고
  백테스트로 측정 불가(README 남은 리스크 4)

- 청산 시점 스프레드 비용 모델 정교화(백로그 우선순위 3) — 하한 ②의 0.25% 스트레스가 대리한다
