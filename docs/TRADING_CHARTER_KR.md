## §0. 최상위 원칙 (The Prime Directives)

1. **감정이 아니라 시스템** — 규칙은 기계가 실행한다. 재량 개입 금지.
2. **안전장치가 전략보다 먼저** — 킬 스위치·손실 한도 없이는 봇을 켜지 않는다.
3. **검증 없이 투입 없음** — RBI(리서치→백테스트→인큐베이션)를 건너뛰지 않는다.
4. **수익은 %가 아니라 기댓값** — `기댓값 = (승률 × 익절폭) − (패율 × 손절폭) − 수수료(왕복 0.1%)` 가 (+)여야만 운용한다.
5. **작게 시작해 점진 확대** — 검증 전 단계는 돈이 아니라 시스템을 검증하는 단계다.

## §1. 적용 범위와 대상

- **거래소**: 업비트 (Open API: REST + WebSocket).
- **마켓**: 원화(KRW) 마켓. **거래 유니버스는 24h 거래대금 상위 top-6 코인을 동적 선정**(v1.2, §13 파라미터표). 거래대금 하한 100억원 미달 코인·스테이블코인(USDT/USDC/DAI/TUSD/BUSD)·블랙리스트 코인은 제외하며, 10분(600초)마다 재조회한다. 조회 실패 시 직전 캐시 유지, 캐시도 없으면 폴백 유니버스(BTC, ETH)로 대체한다.
- **방향**: 현물 롱(매수) 전용. (업비트 현물은 공매도 불가 → 숏 전략은 §11에서 폐기)
- **기준 봉(timeframe)**: 5분봉 기본. (전략별 최적 봉은 백테스트로 확정)
- **자본**: 실계좌 총자산(원화 가용+잠금 + 보유코인 평가액)을 매 tick 동적으로 읽어 사용한다(v1.1, §7.1 참조). 3전략에 균등 배분(자본의 33%씩). 90,000원은 DRY_RUN(모의) 및 계좌 조회 실패 시의 폴백 기본값일 뿐이다.

## §2. 전략 정의 (Entry Signals)

### 가동 전략 (v1.4) — RSI(2) 눌림목 되돌림 (5분봉 + 15분봉 병행)

| 항목 | 규칙 | 이유 |
|---|---|---|
| 진입 ① | **RSI(2) ≤ 3** | 극단적 단기 과매도(최근 10분이 거의 전부 하락) |
| 진입 ② | **1시간봉 EMA200 위**(직전 완성봉 기준) | 상승 추세의 눌림만 매수. 하락장 진입은 −0.25%/거래 |
| 진입 ③ | **ATR(14)/가격 ≥ 0.6%** | 변동성 게이트. 되돌림 폭이 비용(수수료 0.1%+스프레드)을 넘어야 한다. **이 조건이 없으면 전략 전체가 음의 기댓값** |
| 청산 | **RSI(2) ≥ 70** / 익절 +2.5% / 손절 −2.5% / 시간손절 96봉(8시간) | 주 청산 경로는 RSI 되돌림 완료 |
| 레짐 필터 | **미적용** | ADX 필터는 기댓값 개선이 확인되지 않았고(§8), 검증 시에도 쓰지 않았다 |

위 표는 **5분봉(rsi2)** 기준이다. v1.4에서 같은 신호를 **15분봉(rsi2_15m)** 에도 적용해 병행한다.
15분봉은 파라미터를 봉 길이에 맞춰 재검증했다 — 게이트 **ATR≥1.0%**, 손절·익절 **3.0%**, 시간손절 **32봉(8시간, 5분봉 96봉과 동일 시간)**.

**15분봉을 병행하는 이유**: '한 봉 평균 움직임 vs 왕복비용 0.15%' 비율이 5분봉은 0.196%(비용이 77%),
15분봉은 0.323%(46%)다. 비용 부담이 절반이라 거래당 엣지가 크고, 신호 시점이 달라 거래 기회도 늘어난다.

| 구성 | 홀드아웃 거래 | 승률 | PF | 거래당 | t | 계좌 | MDD | 빈도 |
|---|---|---|---|---|---|---|---|---|
| rsi2 (5분봉) | 553 | 69.1% | 1.49 | +0.180% | +3.48 | +32.7% | 5.9% | 0.78/일 |
| rsi2_15m (15분봉) | 188 | 73.9% | 1.96 | +0.489% | +3.75 | +32.8% | 5.2% | 0.26/일 |
| **병행(동시 3포지션)** | 741 | 70.3% | **1.64** | +0.259% | **+5.06** | **+51.4%** | 6.2% | **1.21/일** |

검증 조건: 2년 5분봉·저스프레드 6종목·홀드아웃 17개월(선택 미관여)·수수료 0.1% + 종목별 실측 스프레드·
신호 다음 봉 시가 진입. 상세: `upbit-rbi-bot/backtesting/research/README.md`

- **빈도는 변동성에 종속된다.** 2024Q4처럼 변동성이 큰 국면엔 하루 6회, 2026년처럼 조용한 국면엔 **0회**다. 신호가 없으면 매매하지 않는 것이 정상 동작이다(§0.4).

## §3. 진입 규칙 (Entry Rules)

- **R3.1** 해당 전략의 진입 신호가 발생한 경우에만 진입한다. **신호 없으면 진입하지 않는다**(과매매 금지).
- **R3.2** 진입 대상은 **§1의 동적 스크리닝으로 선정된 유니버스**(거래대금 상위 top-6)에 한한다(슬리피지·갭 회피).
- **R3.2-a (v1.3) 호가 스프레드 상한 0.1%** — 거래대금 상위여도 `(매도호가−매수호가)/중간가 > 0.1%` 인 종목은 제외한다.
  업비트 KRW는 가격대별 호가 단위(tick)가 고정이라 **가격이 낮은 코인은 한 틱이 이미 0.2~0.9%** 다.
  실측(2026-07-26): DOGE 0.930%, ADA 0.412%, TRX 0.206% vs BTC 0.067%, BCH 0.033%.
  왕복 스프레드가 거래당 기댓값(≈0.18%)을 넘으면 **어떤 신호로도 구조적 손실**이다(검증된 전략조차 계좌 −64%).
  오더북 조회 실패 시에는 **직전에 검증된 유니버스 또는 폴백**을 쓰고, 스프레드 미확인 종목으로는 거래하지 않는다.
- **R3.2-c (v1.6) 추적 종목 풀 15개 · 거래대금 하한 30억** — 실측(2026-07-26)으로 확인한 병목:
  스프레드 ≤0.1%를 통과하는 KRW 종목이 **18개**인데, ①거래대금 100억 하한이 그중 5개만 남기고
  ②후보 스캔을 상위 24개로 제한해 **12개를 아예 검사하지 않아** 실제 풀이 3~5개였다.
  스프레드 통과 종목은 거래대금 순위와 무관하게 흩어져 있다(SOL 27위·AVAX 29위·SUI 36위·ATOM 120위).
  → `UNIVERSE_TOP_N` 6→**15**, 거래대금 하한 100억→**30억**, 후보 스캔 배수 4→**8**(120종목).
  거래대금 하한을 낮춘 근거: 주문금액 30,000원은 하루 거래대금 30억의 **0.001%** 로 시장충격이 없고,
  체결 품질은 스프레드(≤0.1%)와 최우선호가 잔량(≥30,000원)이 직접 보장한다.
  **동시 보유 한도(3개)는 그대로**이므로 풀이 커져도 리스크 노출은 늘지 않는다 — 늘어나는 것은 '기회'다.
- **R3.2-d (v1.7) 스프레드 안정성** — 순간 스냅샷이 좁다고 거래해선 안 된다.
  실측(2026-07-26): **LPT 스프레드가 스냅샷 0.044% vs 8회 중앙값 0.245%** 로 크게 흔들렸다.
  진입 직전 확인(§6.7)은 **진입 쪽만** 보장한다 — 청산 시점 스프레드는 진입할 때 알 수 없다.
  → 유니버스 갱신마다 종목별 스프레드를 기록하고(최근 6회 = 1시간), 관측이 3회 이상 모이면
  **중앙값 ≤ 0.1% AND 최댓값 ≤ 0.2%** 를 요구한다. 못 넘으면 '가끔만 좁아지는 종목'으로 보고 제외.
  (실제로 이 규칙 없이 LPT를 거래해 한 건 이익을 봤지만, 왕복비용 0.345%는 거래당 기댓값 0.26%를
   초과하므로 반복하면 손실이다 — 그 이익은 급등에 따른 운이었다.)
- **R3.2-e (v1.8) 측정근거 블랙리스트** — 동적 안정성 필터(§3.2-d)는 관측 3회가 쌓여야 작동한다(재시작 시 초기화).
  이미 8회 샘플링으로 비용 초과가 확인된 종목은 `UNIVERSE_BLACKLIST` 로 즉시 차단한다.
  2026-07-26 측정 중앙값: **LPT 0.245% · ICP 0.190% · AXS 0.153%** (왕복비용 0.25~0.35% > 기댓값 0.26%).
  스프레드가 개선되면 재측정(`spread_check.py --sample mid`) 후 해제한다.
- **R3.2-f (v1.9) 신규 편입 종목은 개별 검증 후 유지** — 스프레드가 좁아도 신호가 안 먹히는 종목이 있다.
  풀 확대(v1.6)로 편입 가능해진 종목을 라이브와 동일 파라미터로 2년 백테스트한 결과
  (`lab_universe.py`, 추가 튜닝 없음 = 전 구간 OOS):
  ATOM **+0.416%** · ENS +0.078% · SUI +0.069% · GAS +0.033% → 유지,
  **KAITO −0.046%**(353거래) → 차단. 비용 필터(§3.2-a~e)와 **별개로** 종목별 기댓값을 확인해야 한다.
- **R3.2-g (v2.0) 거래대금 하한 1억 + 투자경고·주의 제외 + 전수 스캔** — 기존 하한(100억→30억)은
  **근거 없이 잡은 보수적 값**이었다. 손익에 직접 영향을 주는 것은 ①스프레드 ②최우선호가 잔량
  ③종목별 기댓값이며, 거래대금은 그 **대리 지표**에 불과하다 — 세 가지를 모두 직접 측정하므로 중복이다.
  거래대금이 실제로 대리하던 위험(시세조작·급등락)은 업비트 **투자경고(warning)·투자주의(caution)
  플래그**(`market/all?isDetails=true`)로 직접 차단한다.
  실측 통과 종목: 30억 7개 → 10억 12개 → **1억 18개**(더 낮춰도 스프레드가 막아 늘지 않음).
  1억을 남긴 이유는 '실제로 거래가 일어나는지'의 최소 확인선(하루 1억 ≈ 분당 7만원).
  또한 스캔 범위를 **하한을 넘는 전 종목**으로 넓혔다(ATOM 120위처럼 순위 밖 종목을 놓치지 않기 위해).
  적용 결과: 유니버스 3 → **12종목**(BTC·XRP·ETH·SOL·AVAX·ETC·NEAR·LINK·TRUMP·ATOM·GAS·ORCA).
- **R3.2-b (v1.5) 최소 상장 경과일 365일** — 상장 1년 미만 종목은 제외한다.
  거래대금 상위만 보면 **상장 당일 코인이 1위로 올라온다**(2026-07-26 실측: EUL 상장 0일·587억 1위).
  신규 상장 코인은 변동성이 극단적이라 §2의 ATR 게이트를 아주 쉽게 통과하므로, 필터가 없으면
  **전략이 오히려 미검증 종목을 선호하는 선택 편향**이 생긴다. 검증은 2년 히스토리 종목에서만 했다.
  상장일 조회 실패는 '신규 상장'과 구분해 그 주기에만 보류하고 다음 주기에 재시도한다
  (실패를 영구 캐시하면 레이트리밋 한 번에 오래된 종목이 영구 제외된다 — 실제 겪은 버그).
- **R3.3** **동일 코인·동일 방향 중복 진입 금지** — 이미 보유 중이면 다른 전략이 같은 코인에 진입하지 않는다(3배 베팅 방지).
- **R3.4** **동시 보유 최대 3포지션**. (v1.4: '전략당 1개' 제약 해제 — 성적을 낸 포트폴리오
  시뮬레이션이 동시 3포지션을 가정했으므로 라이브를 맞춘다. 한 전략이 서로 다른 코인에 동시
  진입할 수 있고, 포지션 식별자는 `전략:코인` 이다. **동일 코인 중복은 R3.3으로 계속 금지**한다.)
- **R3.5** 진입 주문은 §6(주문 집행) 규칙을 따른다.
- **R3.6** 서킷 브레이커(§5) 발동 중에는 신규 진입을 하지 않는다.

## §4. 청산 규칙 (Exit Rules)

> **폐기됨**: "당일 매수-청산" 대원칙은 업비트(24시간 시장)에서 폐기. 아래 가격 기반 + 시간 손절 조합으로 대체(§11 참조).

우선순위 순으로 평가하며, **먼저 충족되는 조건에서 청산**한다.

- **R4.1 익절(TP) 도달** → 청산.
- **R4.2 손절(SL) 도달** → 청산. (손절 주문은 시장가 허용 — 반드시 나가야 함)
- **R4.3 역방향 신호 발생** → 청산 (선택 적용, 백테스트로 유효성 확인 후).
- **R4.4 죽은 포지션(Dead Position) 청산** → 아래 중 **하나라도(OR)** 충족 시 청산.

**손절/익절 기본값 (v1.2, ATR 완전정규화)**: 고정 %가 아니라 **진입 시점 ATR(Average True Range)의 배수**로 손절·익절 거리를 정한다.
`손절거리 = atr_stop_mult(k) × entry_atr`, `익절거리 = rr × 손절거리`. 이 값은 **진입 시점에 한 번 계산되어 확정**되며(트레일링 아님), 포지션 보유 중 ATR이 변해도 재계산하지 않는다.

| 전략 | atr_stop_mult (k) | 손익비(rr) | 손절거리 | 익절거리 |
|------|---------------------|------------|----------|----------|
| MACD | 1.5 | 2.0 | 1.5×ATR | 3.0×ATR |
| RSI 평균회귀 | 1.2 | 1.6 | 1.2×ATR | 1.92×ATR |
| CVD | 1.3 | 1.7 | 1.3×ATR | 2.21×ATR |

ATR을 구할 수 없는 경우(캔들 데이터 부족, 조회 실패 등)에는 손절거리비율을 고정 폴백값 `FALLBACK_STOP_RATIO = 3%`로 대체한다.

**원칙**: 변동성이 큰 코인일수록 ATR이 커서 손절/익절 거리(원화 기준)가 자동으로 넓어지고, 사이징(§7)에서 포지션 크기가 축소되어 모든 코인이 **동일한 원화 리스크(자본 1%)** 를 지도록 정규화된다. 익절/손절 폭은 **왕복 수수료(0.1%)를 충분히 이길 만큼** 커야 한다(초단타 스캘핑 금지).

**고정 손절 예외 (v1.3)**: 백테스트로 검증된 전략은 ATR 배수 대신 **검증된 고정 손절비율**을 쓸 수 있다(`StrategySpec.stop_pct`). rsi2 는 손절·익절 모두 **2.5% 고정**이다 — 검증에서 이 값이 최적이었고, ATR 배수로 환산하면 재현되지 않는다.

**손익비 규칙 개정 (v1.3)**: v1.2까지의 "모든 전략 손익비 ≥1.5"는 폐기한다. 손익비만으로는 기댓값을 보장하지 못한다 — 실제로 손익비 1.6~2.0인 macd/rsi/cvd는 전부 음의 기댓값이었고, **손익비 1.0에 승률 69%인 rsi2만 §11을 통과**했다. 새 규칙:

- ATR 기반 전략: 손익비 ≥ 1.5
- 고정 손절 전략: 손익비 ≥ 1.0 **AND** 손익분기 승률 `1/(1+rr)` 을 백테스트에서 유의하게 상회 (rsi2: 요구 50% vs 실측 69%)

### §4-A. 죽은 포지션 판정 기준 (R4.4 상세)

| 기준 | 판정 (5분봉 출발값) | 목적 |
|------|---------------------|------|
| **시간 손절**(메인) | 진입 후 **24봉(2시간)** 경과 & TP·SL 미도달 (전략별 상향 가능 — **rsi2 96봉·rsi2_15m 32봉 = 각각 8시간**, v1.3~v1.4) | 신호 엣지 만료 |
| **횡보/무변동** | 최근 **12봉** 동안 진입가 ±0.5% 이탈 실패 | 변동성 소멸 |
| **신호 소멸** | MACD 히스토그램 0 수렴 / RSI 45~55 중립 복귀 | 진입 근거 소멸 |
| **변동성 축소** | ATR이 진입 시 대비 50% 이하 (백테스트 후 채택) | 움직일 힘 소진 |

**부가 규칙 적용 범위 (v1.3)**: 위 표의 **횡보·신호소멸·변동성축소** 세 규칙은 백테스트로 검증되지 않았다. 검증된 전략에 이를 켜면 백테스트와 다른 전략이 되어 성적을 재현할 수 없으므로, 전략별로 선택 적용한다(`StrategySpec.use_dead_extras`). **rsi2·rsi2_15m 는 시간손절만 사용**한다(검증 조건과 동일).

- 죽은 포지션 청산은 **손실 청산이 아니라 본전 ±α에서 자본을 회전**시키는 조치다.

## §5. 리스크 관리 — 서킷 브레이커 (Risk Limits)

- **R5.1 1거래 최대 손실** = **총자본의 1%**(90,000원 기준 **900원**). 손절거리(v1.2부터 ATR 기반, §4)가 넓은 코인일수록 포지션 크기를 줄여 손실액을 900원에 맞춘다. → §7과 연동.
- **R5.2 일일 손실 한도** = 당일 누적 손실 **총자본 −3%**(−2,700원) 도달 시 → **그날 신규 진입 전면 중단**(기존 포지션은 SL/TP까지 유지).
- **R5.3 연속 손실 차단** = **연속 5회 손절** 시 → 봇 일시정지 + 알림.
- **R5.4 최대 낙폭(MDD) 차단** = 누적 자본이 고점 대비 **−15%** 도달 시 → **전 봇 정지, 수동 재검토 전 재가동 금지**.
- **R5.5 동시 노출 한도** = 최대 3포지션 / 총노출 ≤ 자본 100%.

## §6. 주문 집행 (Order Execution)

- **R6.1** **진입·익절·죽은포지션 청산은 지정가(Limit) 우선** — 수수료·슬리피지 최소화.
- **R6.2** **손절(SL)은 시장가 허용** — 체결 확실성 우선(반드시 빠져나가야 함).
- **R6.3** 지정가 미체결 시: 제출 후 **30초 내 미체결이면 취소 → 신호 유효 시 1회 재주문 → 그래도 미체결이면 해당 봉 진입 포기**(추격매수 금지).
- **R6.4** 부분체결분은 **실제 체결 수량 기준**으로 SL/TP·손익을 계산한다.
- **R6.5** 최소주문금액(업비트 5,000원) 이상을 준수한다.
- **R6.6** 신규 주문 전 해당 코인의 미체결 잔량을 조회·정리하여 **중복 주문을 방지**한다.
- **R6.7 진입 직전 스프레드 재확인 (v1.6)** = 주문을 내기 바로 전에 해당 종목의 호가 스프레드를 다시 조회해 상한(0.1%)을 넘으면 **진입을 취소**한다. 유니버스는 10분 주기로 갱신되므로 스크리닝 시점의 스프레드는 최신이 아니며, 거래당 기댓값이 0.26% 수준이라 스프레드 0.1%p 차이가 손익을 가른다. 조회 실패도 진입 금지로 처리한다(비용 미확인 상태로 실거래 금지). 종목 풀을 넓힌 v1.6에서 특히 중요하다.

## §7. 포지션 사이징 (Position Sizing)

- **R7.1 자본 정의(v1.1)** = 자본은 고정값이 아니라 **매 tick 실계좌 총자산(원화 가용+잠금 + 보유코인 평가액)** 을 읽어 사용한다. 입금하면 커지고 손실/출금이면 작아진다. 모든 리스크 한도·포지션 크기가 이 자본에 **비례해 자동 스케일**된다. (DRY_RUN 및 조회 실패 시 폴백 `PAPER_CAPITAL_KRW`, 기본 90,000원)
- **R7.1a 기본 배분** = 전략당 자본의 **33%**(자본 90,000원이면 각 30,000원). 주문금액은 **주문가능 원화 이하**로 clamp, 최소주문(5,000원) 미만이면 진입 스킵.
- **R7.2 리스크 상한(우선 적용, v1.2 ATR 정규화)** = 1거래 손실이 **자본 1%(900원)** 를 넘지 않도록 포지션 크기 결정. 손절거리비율(`stop_ratio`)은 고정 %가 아니라 **진입 시점 ATR 기반**으로 계산한다.
  - 공식: `stop_ratio = atr_stop_mult(k) × entry_atr ÷ 진입가`, `포지션 크기 = 900원 ÷ stop_ratio`.
  - ATR을 구할 수 없으면(캔들 부족·조회 실패 등) `stop_ratio = FALLBACK_STOP_RATIO(3%)`를 사용한다.
  - 변동성이 큰 코인일수록 `stop_ratio`가 커져 포지션 크기가 자동으로 축소되고, 변동성이 작은 코인은 포지션 크기가 커진다 → **모든 코인이 동일한 원화 리스크(자본 1%)** 를 지도록 정규화된다.
  - 최종 포지션 크기는 위 값과 **전략당 배분 상한(§7.1a, 33%)**, **주문가능 원화** 중 가장 작은 값으로 clamp한다.
- **R7.3 확장 규칙** = 자본이 커져도 **"1거래 리스크 = 자본 1%, 총노출 ≤ 100%"** 공식을 유지한다.
- **R7.4 점진적 확대** = 검증 통과 후에만 5,000원 → 10,000원 → 30,000원 순으로 규모를 키운다.

## §8. 시장 상태 필터 — 레짐 필터 (Regime Filter)

- **R8.1** 상위 필터(예: 200EMA 기울기 + ADX 또는 변동성)로 현재 장세를 판별한다.
- **R8.2** 레짐별 전략 활성화:
  - **추세장**(ADX 높음/EMA 방향성) → **MACD** on, RSI off.
  - **횡보장**(ADX 낮음/박스권) → **RSI 평균회귀** on, MACD off.
  - **반전 신호 구간** → **CVD** 보조 on.
- **R8.3** 판별 임계값(초기 ADX 25 기준 등)은 백테스트로 확정한다.

## §9. 안전장치 (Failsafe) — 최우선 구현

- **R9.1 킬 스위치** = **전체 청산 + 전 봇 정지** 단일 명령/버튼을 상시 구비한다.
- **R9.2 API 에러/네트워크 끊김** = **신규 진입 즉시 중단**, 기존 포지션 유지. 손절은 가능하면 거래소 예약주문으로 이중화. 복구 시 재개 전 **상태 재동기화**.
- **R9.3 상태 복구** = 봇 재시작 시 거래소 실제 잔고·미체결을 조회하여 내부 상태와 대조·복구(중복 주문 방지).
- **R9.4 하트비트/피드 감시** = 가격 데이터가 **N초 이상 미갱신** 시 자동 정지(멈춘 피드로 매매 금지).
- **R9.5 알림** = 서킷 브레이커 발동·에러·이상 감지 시 **텔레그램 등 즉시 알림**.
- **R9.6 시크릿 관리** = API 키는 `.env`로 분리, 절대 코드/저장소에 하드코딩·커밋하지 않는다. 키 권한은 **거래·조회로 한정, 출금 권한 미부여**.
- **R9.7 헌장 개정 시 모의 모드 강제 (v1.3)** = 매매 규칙이 개정되면 `DRY_RUN=false` 만으로는 실거래가 시작되지 않는다. 환경변수 **`LIVE_CHARTER_ACK=<현재 헌장 버전>`** 이 함께 있어야 하며, 없거나 버전이 다르면 자동으로 모의 모드로 강제하고 텔레그램으로 알린다.
  - 이유: 전략이 교체된 코드가 배포됐는데 **이전 승인으로 실계좌가 계속 도는 것**이 가장 위험하다. 새 규칙은 모의로 먼저 검증한다(§11).
  - 실거래 전환 절차: 모의로 최소 2~4주 관찰 → 실제 체결가·스프레드가 백테스트 가정(수수료 0.1% + 슬리피지 0.05~0.10%) 이내인지 확인 → 서버 `.env`에 `LIVE_CHARTER_ACK=<현재 버전>` 추가 → 재시작.

## §10. 로깅·모니터링·세금 (Observability)

- **R10.1 거래 로그** = 모든 진입/청산/에러를 타임스탬프·전략·코인·가격·수량·사유·손익과 함께 저장(CSV/SQLite).
- **R10.2 실시간 알림** = 진입·청산·에러·리밋 발동 시 텔레그램 알림.
- **R10.3 성과 리뷰** = **주 1회** 전략별 승률·손익비·MDD 재점검. 기준(승률>55%, 손익비>1.5) 미달 전략은 **비활성 후 재백테스트**.
- **R10.4 괴리 추적** = 실전 승률이 백테스트 대비 크게 낮으면 슬리피지·과최적화를 의심하고 점검. 대시보드가 **백테스트 기대치(승률·PF·거래당 기댓값)를 나란히 표시**한다(v1.5).
- **R10.6 전략 세대 분리 (v1.5)** = 전략을 교체하면(§2) 과거 전략의 거래 기록을 현재 성과와 섞지 않는다. 대시보드 기본 조회는 **현재 가동 전략만**이며, 과거 기록은 삭제하지 않고 `scope=all` 로만 본다(§10.5 기록 보존).
- **R10.7 진입 진단 (v1.5)** = 진입하지 않는 이유(RSI·변동성 게이트·상위 추세 중 무엇에 막혔는지)를 대시보드에 노출한다. '신호가 없어 거래가 없는 상태'와 '봇 장애'를 구분하기 위한 것이다.
- **R10.5 세금·기록 보존** = 국내 가상자산 과세에 대비해 전 거래내역·연간 손익을 보존(업비트 거래내역 다운로드 병행).

## §11. 검증·운영 프로세스 (RBI Lifecycle)

1. **리서치(Research)** — 전략 아이디어는 검증된 출처에서(참고문서 §리서치). 새로 발명하지 않는다.
2. **백테스트(Backtest)** — 업비트 캔들 API로 과거 데이터 수집 → **수수료(왕복 0.1%) 반영** 후 검증.
   - **통과 기준**: 승률 > 55%, 손익비 > 1.5, 최대낙폭 < 20%, 표본 100거래 이상.
   - 통과 못하면 **미련 없이 폐기**. 아이디어에 집착 금지.
3. **인큐베이션(Incubate)** — 통과 전략만 **최소금액(5,000원)** 실전 2~4주 관찰 → 이상 없으면 §7-4로 점진 확대.
4. **정기 점검** — 운영 중 몇 시간마다 에러/체결/실전 손익 vs 백테스트 일치 여부 확인.

## §12. Polymarket → 업비트 전환: 폐기·변형 목록

> 참고문서(LIFE_CHANGE)는 Polymarket 기반이므로, 업비트에 맞지 않는 요소는 아래와 같이 **과감히 폐기·변형**한다.

| 원문(Polymarket) 요소 | 처리 | 업비트 대체 |
|------------------------|------|-------------|
| `py-clob-client` SDK / CLOB API | **폐기** | 업비트 Open API (REST + WebSocket), `pyupbit`/`ccxt` 등 |
| 지정가 주문 **무료** 전제 | **폐기** | 지정가·시장가 모두 **0.05%**(왕복 0.1%) → 전 계산에 반영 |
| 확률 토큰 가격(0.01~0.99) | **폐기** | 실제 코인 시세, **%등락 = 손익** |
| 이벤트 "예/아니오" 마켓 | **폐기** | 코인 현물 롱 전용 |
| 다중 계정(계정당 1봇) 병렬 | **변형** | 단일 계정 내 **전략별 논리적 포지션 분리**(업비트 계정 다중화는 지양) |
| `chain_id=137`(Polygon), 지갑키/펀더 | **폐기** | 업비트 **Access/Secret Key** 인증(.env) |
| 만료형 5분 마켓 → "당일청산" | **폐기** | 24시간 시장 → **시간 손절(§4-A)** 로 대체 |
| 숏/양방향 | **폐기** | 업비트 현물은 롱 전용 |
| 병렬 봇 예시 명령/구조 | **참고 유지** | 프로젝트 구조 설계 시 업비트용으로 재구성 |

## §14. 헌장 준수 서약 (Operating Discipline)

- 이 헌장의 규칙은 **예외 없이 코드로 강제**한다. 수동 개입이 필요하면 먼저 헌장을 개정(버전업)한 뒤 코드에 반영한다.
- 모든 수치는 **백테스트 결과로만** 변경한다. "느낌"으로 바꾸지 않는다.
- **안전장치(§9) → 서킷 브레이커(§5) → 포지션 사이징(§7) → 주문 집행(§6)** 순으로 구현·검증한 뒤에야 실거래를 켠다.
